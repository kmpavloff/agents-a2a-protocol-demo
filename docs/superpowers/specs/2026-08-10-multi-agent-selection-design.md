# Дизайн: несколько A2A-агентов в конфиге и выбор агента в UI

Дата: 2026-08-10

## Контекст и проблема

Оркестратор сегодня знает ровно одного удалённого агента: `worker_url` в
`configs/orchestrator.yaml`. На старте он резолвит его AgentCard, выводит из неё имя и
описание единственного делегирующего инструмента (`ProfileFromCard`) и вшивает их в
системный промпт. Вся конструкция — «один оркестратор, один воркер».

Появился второй агент, развёрнутый в локальной сети на `192.168.1.68:18800` — **Ouroboros**.
Он говорит по A2A 1.0 и умеет возвращать A2UI. Нужно: научить оркестратор держать
**произвольное число** удалённых агентов, описывать их в настройках и давать пользователю
выбирать агента прямо в веб-UI.

### Что выяснено про Ouroboros (проверено на живом агенте 2026-08-10)

| Свойство | Значение |
|---|---|
| Транспорт | JSON-RPC 2.0 over HTTP POST на `/` |
| AgentCard | `GET /.well-known/agent.json` (не `agent-card.json`) |
| Аутентификация | HTTP Basic (`securitySchemes.basic` объявлен в карточке) |
| Методы | `SendMessage`, `GetTask`, `ListTasks`, `CancelTask` |
| Состояния | `TASK_STATE_COMPLETED` и т.д. |
| Активация навыка | `params.message.metadata.skill` (например `"shop"`) |
| Латентность | ~52 с на запрос со скиллом |
| Непрерывность | повторный `SendMessage` с тем же `contextId` сохраняет контекст |

Три особенности, которые прямо влияют на дизайн:

1. **`url` в карточке — `http://0.0.0.0:18800/`.** По нему клиент никуда не попадёт; адрес
   транспорта надо брать из конфига, а карточку патчить в памяти перед `NewFromCard`.
2. **97 скиллов в карточке.** `ProfileFromCard` склеил бы из них описание инструмента на
   десятки килобайт — локальная модель на таком промпте бесполезна.
3. **Форма ответа сейчас расходится с контрактом** (см. «Контракт Ouroboros» ниже).

### Совместимость с `a2a-go v2.3.1`

Писать собственный HTTP-клиент не требуется — официальный SDK покрывает контракт:

- `internal/jsonrpc/jsonrpc.go` объявляет ровно те же имена методов;
- `a2a.Message.Metadata map[string]any` — `metadata.skill` уходит штатно;
- `part.Data` имеет тип `*any`, поэтому `"data": [...]` массивом парсится корректно.

Одно ограничение: встроенный `a2aclient.AuthInterceptor` умеет только Bearer
(`auth.go:93` жёстко форматирует `"Bearer %s"`). Basic-auth делаем своим
`http.RoundTripper` и передаём его через `a2aclient.WithJSONRPCTransport(client)`.

### Контракт Ouroboros

Владелец Ouroboros приводит его к контракту (промпт «Задача: реализовать A2A-клиента»,
2026-08-10). Ключевые пункты контракта против того, что агент отдаёт на момент написания
спеки:

| Контракт | Фактическое поведение сегодня |
|---|---|
| текст агента в `result.status.message.parts` | `status` = `{"state": "..."}` без `message`; текст лежит в `artifacts[0].parts[0]` |
| A2UI как `{"data": [ ...сообщения... ], "mediaType": "application/a2ui+json"}` | `{"text": "<JSON-строка>", "mediaType": "application/a2ui+json"}` |
| компоненты плоские: `{"id", "component": "Text", ...}` | обёрнутые: `{"Text": {"id", ...}}` |
| только 18 компонентов basic-каталога v0.9 | плюс собственные `Heading`, `Callout`, `Metric`, `Table` |

Контракт — основной путь. Толерантность к фактическому поведению — постоянный защитный
слой, а не временный костыль: она позволяет связке работать и до, и после правок на
стороне Ouroboros, и переживать его дальнейшие изменения (агент самомодифицирующийся).

Реальный ответ агента сохранён как фикстура: `internal/a2ui/testdata/ouroboros_order_card.json`.

## Цели

- Оркестратор держит произвольное число удалённых A2A-агентов, описанных в конфиге.
- Поддержаны нестандартный путь карточки, Basic-auth, подмена адреса из карточки,
  `metadata.skill` и покомпонентные таймауты.
- В браузере — селектор агента: «Авто» плюс явный выбор конкретного агента.
- При явном выборе агента, помеченного `verbatim`, ответ идёт в браузер **без** локальной
  LLM: текст и A2UI как есть.
- A2UI от чужого агента доезжает до браузера в форме, которую понимает `@a2ui/web_core`.
- Недоступный агент не роняет оркестратор.

## Не-цели (YAGNI)

- Свой A2A-клиент: используем `a2a-go`.
- `ListTasks`/`CancelTask` в UI — реализуем только то, что нужно диалогу (`SendMessage` +
  поллинг `GetTask`).
- Собственные Lit-компоненты для `Heading`/`Callout`/`Metric`/`Table` в браузере —
  деградируем их в basic-каталог на стороне Go.
- Управление агентами из UI (добавление/редактирование) — только чтение конфига.
- Правки на стороне Ouroboros — они вне этого репозитория.
- Java-порт (`java/`) в этой итерации не трогаем.
- Стриминг, push-уведомления, многопользовательские сессии, персист.

## Архитектура

```
браузер                      оркестратор :8080                    удалённые агенты
────────                     ──────────────────                   ─────────────────
<select> агент  ──┐
                  │  A2A message
                  │  metadata.agentId ──▶ orchExecutor
                  │                          │
                  │                    ┌─────┴──────┐
                  │           verbatim │            │ auto / delegate
                  │                    ▼            ▼
                  │              Registry.Get   runner (LLM)
                  │                    │            │ tools = Registry.Tools()
                  │                    ▼            ▼
                  │                 Remote ──────  Remote ──── A2A ──▶ orders-agent :8081
                  │                    │                              Ouroboros 192.168.1.68:18800
                  │                    ▼
                  └────── артефакт ◀── a2ui.Ingest / a2ui.FromWidget
```

## Настройки

```yaml
# configs/orchestrator.yaml
agents:
  - id: orders
    name: "Агент заказов"
    url: "http://localhost:8081"

  - id: ouroboros
    name: "Ouroboros · магазин"
    url: "http://192.168.1.68:18800"
    card_path: "/.well-known/agent.json"
    skill: "shop"
    verbatim: true
    timeout: "180s"
    description: "Заказы интернет-магазина: статус, детали, возвраты."
    auth:
      type: basic
      username: ouroboros
      password: testpass
```

Поля `AgentConfig`:

| Поле | Обяз. | По умолчанию | Смысл |
|---|---|---|---|
| `id` | да | — | Ключ агента: имя инструмента (`ask_<id>`), значение `metadata.agentId`, суффикс env-переменной |
| `name` | нет | имя из карточки | Подпись в селекторе UI |
| `url` | да | — | Базовый адрес; **вытесняет** адрес из карточки |
| `card_path` | нет | `/.well-known/agent-card.json` | Путь к AgentCard |
| `skill` | нет | — | Уезжает в `metadata.skill` каждого сообщения |
| `verbatim` | нет | `false` | При явном выборе ответ идёт мимо локальной LLM |
| `timeout` | нет | `120s` | Таймаут `SendMessage` |
| `description` | нет | вывод из карточки | Описание для промпта; вытесняет карточку |
| `auth` | нет | без auth | `{type: basic, username, password}` |

Правила:

- **Имя инструмента — `ask_<id>`**, а не производное от имени агента. У Ouroboros имя
  «Who I Am», из которого `sanitizeToolName` дал бы `ask_Who_I_Am`.
- **`description` вытесняет карточку.** Если задан — `ProfileFromCard` для этого агента не
  используется вовсе (иначе 97 скиллов Ouroboros утопят промпт). Если не задан — работает
  нынешний вывод из карточки, без изменений.
- **Пароль.** `configs/*.yaml` в gitignore, поэтому инлайн допустим. Перекрытие —
  `A2A_AGENT_<ID>_PASSWORD` (`ID` в верхнем регистре, дефисы → подчёркивания).
- **Совместимость.** Если `agents:` пуст, из `worker_url` синтезируется единственная запись
  `{id: orders, name: "Агент заказов", url: <worker_url>}`. Существующие конфиги,
  `docker-compose.yml`, TUI-режим и Java-порт продолжают работать без правок.
- **Валидация:** `id` уникален и матчит `^[a-z][a-z0-9_-]*$`; `url` непуст; хотя бы один агент.
- **Терминальный режим (без `--web`)** выбора агента не получает: REPL работает с первым
  агентом списка, то есть при миграции с `worker_url` — ровно как сегодня. Селектор — только
  браузерная функция.

## Компоненты

### `internal/config` — разбор списка агентов

Добавляются `AgentConfig`/`AuthConfig`, поле `Agents []AgentConfig` в `OrchestratorConfig`,
миграция `worker_url` и валидация. `WorkerURL` остаётся в структуре ради совместимости.

### `internal/a2abridge/remote.go` — `Remote`: одно соединение с одним агентом

Одна ответственность — транспорт и сессии A2A. Умеет:

- резолв карточки по `card_path` с Basic-auth (`agentcard.Resolver` + `ResolveOption`);
- подмену `card.URL` и `card.SupportedInterfaces[].URL` адресом из конфига;
- клиент через `a2aclient.WithJSONRPCTransport(httpClientWithBasicAuth)`;
- `Ask(ctx, sessionID, text) (Result, error)`: подставляет `metadata.skill`, переиспользует
  `contextId` сессии, при `WORKING`/`SUBMITTED` опрашивает `GetTask` раз в 2 с до таймаута;
- хранение `pendingTask` на сессию — для `input-required` (нужно воркеру, безвредно остальным);
- `Result` = `{Text string, A2UI []map[string]any, Widgets []map[string]any, Files []attachedFile}`.

Ленивая инициализация: карточка резолвится при первом обращении, а не на старте. Ошибка
резолва не фатальна — агент помечается недоступным и повторяет попытку на следующем запросе.

Нынешний `OrdersClient` переезжает на `Remote`, сохраняя своё поведение: пустые сообщения,
счётчик `emptyCalls`, `NEEDS_USER_INPUT`, HITL-возвраты и виджеты воркера остаются как есть.

### `internal/a2abridge/registry.go` — `Registry`

`id → *Remote`, собирается из конфига. Даёт `Get(id)`, `List()` (для `/api/agents`) и
`Tools()` (набор adk-инструментов для режима «Авто»). Знает, какие агенты недоступны.

### `internal/a2ui/ingest.go` — `Ingest(parts) []map[string]any`

Единственное место, знающее, как выковырять A2UI из ответа чужого агента. Принимает:

- `DataPart`, где `data` — массив A2UI-сообщений (контракт);
- `DataPart`, где `data` — одно сообщение;
- **текстовую** часть с `mediaType: application/a2ui+json`, внутри которой JSON-строка
  (фактическое поведение сегодня).

Нормализация компонентов:

| Вход | Выход |
|---|---|
| `{"id", "component": "Text", ...}` | пропускается без изменений |
| `{"Text": {"id", ...}}` | разворачивается в плоскую форму |
| `Heading` | `Text` с `variant: "h3"` |
| `Callout` | `Column` из `Text`(заголовок, `h3`) + `Text`(тело) |
| `Metric` | `Text` вида `**Лейбл:** значение` |
| `Table` | `Text` с markdown-таблицей (браузер отрисует настоящей `<table>`) |
| `Button` с `label` вместо `child` | `Button` + дочерний `Text` |
| прочее незнакомое | `Text` с JSON-дампом свойств; сообщение в трейс |

Инвариант: `Ingest` **никогда не паникует и не возвращает ошибку** — худший исход — блёклый,
но валидный набор компонентов. Чужой агент не должен ронять наш UI.

Существующий путь воркера (`FromWidget` для `widget/order`, `widget/confirmation` и прочих)
не трогается.

### `internal/a2abridge/orchserver.go` — маршрутизация

Выбор агента приезжает в метаданных A2A-сообщения — тем же механизмом, каким Ouroboros
принимает скилл: `{"metadata": {"agentId": "ouroboros"}}`.

| `agentId` | Поведение |
|---|---|
| `auto` / пусто / неизвестный id | Как сейчас: LLM с инструментами всех агентов; виджеты минуют модель |
| агент с `verbatim: true` | LLM не вызывается; текст и A2UI агента идут в артефакт как есть |
| остальные | LLM ровно с одним инструментом выбранного агента |

Неизвестный `agentId` тихо откатывается в «Авто» с записью в трейс — рассинхрон конфига и
кэша браузера не должен ломать диалог.

Существующие A2UI-действия (`approve_refund`, `decline_refund`, `submit_refund_details`) и
прямой resume задачи воркера мимо LLM работают как раньше.

**Сессии.** У каждого агента свой `contextId` внутри браузерной сессии (ключ —
`sessionID + agentID`), поэтому переключение агента туда-обратно не рвёт ни одну из ниток
разговора.

**Смена набора инструментов.** Runner создаётся под набор инструментов, поэтому «Авто» и
явный выбор требуют разных `agent.Agent`. Собираются лениво и кэшируются по `agentId`.

### `internal/webui` + `web/src` — селектор

- `GET /api/agents` рядом с раздачей статики: `[{id, name, description, verbatim, available}]`.
- `app.ts`: `<select>` над лентой, первый пункт «Авто», выбор в `localStorage`. Недоступные —
  `disabled` с пометкой. Строка ожидания — «Ouroboros печатает…» (при 52 с важно понимать,
  кого ждём).
- `client.ts`: прокидывает `metadata.agentId`, поднимает таймаут.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Агент недоступен на старте | Оркестратор стартует; агент помечен `available: false`; резолв повторяется при обращении |
| Агент недоступен при запросе | Понятный текст пользователю; остальные агенты работают |
| HTTP 401 | Сообщение про Basic-auth, с именем агента; в трейс — без пароля |
| JSON-RPC error | Код и message в трейс; пользователю — короткий текст |
| Задача висит в `WORKING` дольше таймаута | Прекращаем поллинг, сообщаем о таймауте |
| A2UI не распознан | `Ingest` возвращает что смог; при пустом результате отдаём только текст |

## Тестирование

Go:

- `internal/config`: разбор `agents`, миграция `worker_url`, `A2A_AGENT_*_PASSWORD`,
  ошибки валидации (дубль `id`, пустой `url`, плохой `id`).
- `internal/a2abridge/remote_test.go`: `httptest`-сервер по контракту — карточка по
  нестандартному пути, 401 без auth, наличие `metadata.skill` в теле, подмена адреса из
  карточки, поллинг `GetTask` при `WORKING`, таймаут.
- `internal/a2ui/ingest_test.go`: golden-тесты на сохранённой фикстуре реального ответа
  Ouroboros **и** на форме из контракта; на каждый вид деградации; на мусорном вводе
  (не паникует).
- `internal/a2abridge/orchserver_test.go`: `verbatim` не дёргает LLM; «Авто» видит все
  инструменты; явный выбор — ровно один; неизвестный `agentId` откатывается в «Авто».
- `internal/webui`: `/api/agents` отдаёт список из конфига.

Тесты не ходят в сеть и не требуют ни LM Studio, ни живого Ouroboros: удалённый агент
всюду поднимается `httptest`-сервером, LLM — существующим детерминированным стабом.

Ручная проверка через `.claude/skills/verify` — сборка и прогон обоих агентов.

## Риски

| Риск | Смягчение |
|---|---|
| Ouroboros меняет формат ответа (самомодифицирующийся агент) | Толерантный `Ingest` + golden-фикстура; расхождение видно как деградация, а не как падение |
| ~52 с на запрос выглядят как зависание | Спиннер с именем агента; таймаут в конфиге |
| Локальная модель в «Авто» путает агентов | Явный выбор — основной сценарий; «Авто» — демонстрационный |
| Пароль утекает в трейс/лог | Basic-заголовок ставится в `RoundTripper` и не логируется; в трейсе — только имя агента |
| Java-порт отстаёт от Go | Осознанная не-цель этой итерации; зафиксировать в `java/README.md` |
