# Настройка интеграции с агентами из UI

Дата: 2026-08-31

## Задача

Сейчас список удалённых A2A-агентов живёт только в `configs/orchestrator.yaml`:
он читается один раз на старте в `a2abridge.Registry`, который после этого
неизменяем, а браузер получает его на чтение через `GET /api/agents`. Чтобы
подключить нового агента или починить опечатку в его адресе, приходится править
файл и перезапускать оркестратор.

Нужно завести агентов, править и удалять их прямо из веб-интерфейса, чтобы
изменения действовали немедленно.

## Решения

| Вопрос | Решение |
|---|---|
| Куда пишутся правки | Отдельный overlay-файл; `configs/orchestrator.yaml` остаётся рукописным |
| Объём операций | Полный CRUD, включая агентов, пришедших из YAML |
| Когда действует | Немедленно, без перезапуска |
| Пароли | Записываются, но никогда не отдаются наружу |
| Место в UI | Отдельный экран «Настройки» рядом с «Чатом» |
| Доступ к API | Без ограничений, как и весь остальной демо-стенд |

## Хранилище и слияние

Overlay лежит в `configs/agents.local.yaml` (в `.gitignore`, рядом с уже
нетрекаемым `orchestrator.yaml`). Путь настраивается полем
`agents_overlay_path` оркестратора, значение по умолчанию — этот файл.

```yaml
# Управляется из UI. Правки руками будут перезаписаны.
agents:
  - id: ouroboros          # запись целиком перекрывает YAML-агента с тем же id
    name: "Ouroboros · магазин"
    url: "http://192.168.1.68:18800"
    verbatim: true
    auth: {type: basic, username: ouroboros, password: test}
  - id: orders
    hidden: true           # YAML-агент, удалённый через UI
```

Правила слияния в новом пакете `internal/agentstore`:

1. база — `agents:` из `orchestrator.yaml`, в порядке объявления;
2. overlay-запись с совпавшим id заменяет запись **целиком**, позиция
   сохраняется;
3. `hidden: true` — агент выпадает из списка;
4. записи с незнакомыми id добавляются в конец, в порядке overlay (это
   заведённые через UI);
5. env-перекрытия (`A2A_AGENT_<ID>_URL`, `A2A_AGENT_<ID>_PASSWORD`)
   применяются **после** слияния — за ними остаётся последнее слово, как и
   сейчас.

Overlay разбирается в собственный тип `agentstore.Override` — это
`config.AgentConfig` плюс поле `Hidden bool`: в самой `AgentConfig` такому полю
не место, оно описывает не агента, а решение UI его спрятать.

Перекрытие целой записью, а не по отдельным полям, выбрано осознанно:
перекрытый агент целиком принадлежит UI (правка его полей в YAML больше не
видна, зато в форме есть «Сбросить к конфигу», удаляющая overlay-запись), а
неперекрытые агенты продолжают жить из YAML, включая добавленных туда новых.

Пункт 5 даёт неприятный угол: в `docker-compose` уже задан
`A2A_AGENT_ORDERS_URL`, и правка URL из UI молча ни на что не повлияет. Поэтому
`GET` помечает такие поля (`envLocked`), а форма их блокирует с подписью
«перекрыто переменной окружения».

Запись атомарная: временный файл рядом с целевым плюс `os.Rename`.

## HTTP API

`Go 1.26`, шаблоны `http.ServeMux` с методом и `{id}`.

| Метод | Путь | Смысл |
|---|---|---|
| `GET` | `/api/agents/config` | полный список записей: поля конфига, `source: file\|ui`, `auth.hasPassword`, `envLocked`; **пароль не отдаётся никогда** |
| `POST` | `/api/agents/config` | создать (id должен быть свободен) → 201 |
| `PUT` | `/api/agents/config/{id}` | заменить; пустой `password` = оставить прежний → 200 |
| `DELETE` | `/api/agents/config/{id}` | UI-агента убрать из overlay, файлового пометить `hidden` → 204 |
| `POST` | `/api/agents/config/{id}/reset` | забыть overlay-запись, вернуть YAML-версию (в том числе снять `hidden`) → 200 |

Поля JSON — в camelCase: `cardPath`, `envLocked`, `auth.hasPassword`. Скрытые
(`hidden: true`) файловые агенты в этом списке остаются, с флагом `hidden`:
иначе вернуть удалённого агента можно было бы только правкой файла. В
`/api/agents`, который питает селектор чата, они не попадают.

Валидация — существующая из `internal/config` (id по `^[a-z][a-z0-9_-]*$`,
непустой url, разбираемый timeout, `auth.type ∈ {"", "basic"}`), вынесенная в
экспортируемую функцию. Невалидная запись — `400` с `{"error": "…"}`.

Эндпоинты ничем не защищены, как и `/invoke`. Значит, оркестратор в режиме
`--web` нельзя выставлять за пределы доверенной сети: по этому API можно
подменить адрес агента и увести туда трафик. Предупреждение идёт в README.

## Живое применение

`Registry` получает `Apply(agents []config.AgentConfig)`:

- сверка по id; `config.AgentConfig` состоит только из строк и bool, поэтому
  сравнение — обычное `==`;
- **совпало** — `*Remote` остаётся тем же: живое соединение, разобранная
  карточка и зависшие `input-required` задачи целы;
- **изменилось** — `*Remote` пересоздаётся, вместе с ним выбрасывается и
  кэшированный `*OrdersClient`. Править `cfg` на месте нельзя: `ID()`,
  `Name()`, `Verbatim()` читают его без мьютекса;
- **исчезло** — запись удаляется из `remotes` и `clients`;
- `order` перестраивается по новому списку, счётчик поколений растёт.

Обработчики виджетов вешаются иначе, чем сейчас. `NewOrchestratorExecutor`
один раз проходит по `reg.IDs()` и ставит на каждого клиента
`SetWidgetHandler`/`SetA2UIHandler`/`SetFileHandler`; клиент, созданный после
этого прохода, остался бы без них — новый агент отвечал бы текстом, а его
виджеты молча пропадали. Поэтому разовый цикл заменяется на
`Registry.SetClientInit(func(*OrdersClient))`, который вызывается в `ClientFor`
при создании любого клиента.

Исполнитель кэширует runner'ы (`runners[agentID]`, для «Авто» — ключ по именам
инструментов). В `runnerFor` добавляется сверка поколения реестра: изменилось —
карта чистится целиком. Иначе после правки описания агента модель работала бы
со старым промптом, а после удаления звала бы несуществующий инструмент.

Терминальный REPL правок на ходу не получает: он читает слитый список на старте
и работает с первым агентом, как раньше. Селектор в браузере подхватывает
изменения своим опросом `/api/agents` раз в 30 с, а экран настроек дополнительно
дёргает его сразу после сохранения.

## Интерфейс

В `app.ts` появляется состояние `_tab: 'chat' | 'settings'` и переключатель
«Чат / Настройки» над шапкой; выбор отражается в `location.hash`, чтобы
перезагрузка не выкидывала обратно в чат. Лента чата при переходе **не
размонтируется**, а скрывается стилем: в `_items` лежат живые A2UI-поверхности,
и пересоздавать `<a2ui-surface>` на каждом переключении вкладки — напрашиваться
на «Surface … already exists».

Форма живёт в новом компоненте `web/src/agent-settings.ts`
(`<agent-settings>`), самодостаточном: он сам читает `GET /api/agents/config` и
сам пишет. `app.ts` (уже 676 строк) прирастает только вкладками. О сохранении
компонент сообщает событием `agents-changed`, по которому `app.ts` перечитывает
`/api/agents`.

Слева — список агентов с бейджами «из файла» / «изменён в UI» и живым статусом
(`available`/`probed` из `/api/agents`: данные уже есть, а сразу после ввода
URL это главный вопрос — «отвечает или я опечатался»). Справа — форма:

- `id` — редактируется только при создании; у существующего только для чтения
  (смена id — это удалить и завести заново);
- `name`, `url`, `card_path`, `skill`, `timeout`, `description`, галка
  `verbatim`;
- `auth.type` (`—` / `basic`), `username`, `password` — тип `password`, пустое
  поле с подписью «оставьте пустым, чтобы не менять»; если пароль уже задан,
  рядом «задан»;
- поля из `envLocked` — заблокированы, с подписью «перекрыто переменной
  окружения»;
- у изменённого файлового агента — «Сбросить к конфигу»; удаление — через
  подтверждение;
- скрытый файловый агент показан в списке приглушённым, с бейджем «скрыт» и
  действием «Вернуть» (тот же `reset`);
- ошибка `400` от сервера показывается над кнопками, форма не закрывается.

## Проверка

Разработка по TDD. Тесты на Go:

- `agentstore` — перекрытие по id с сохранением позиции, `hidden`, снятие
  `hidden` через `reset`, новые записи в конец, env поверх слияния, атомарная
  запись, отказ на невалидной записи;
- обработчики — `GET` не отдаёт пароль, но отдаёт `hasPassword`;
  `POST`/`PUT`/`DELETE`/`reset` дают ожидаемые коды и содержимое overlay;
  пустой пароль в `PUT` сохраняет прежний;
- `Registry.Apply` — неизменившийся агент остаётся тем же указателем,
  изменившийся заменён, удалённый исчез, поколение растёт; `SetClientInit`
  срабатывает для клиента, созданного уже после старта;
- исполнитель — смена поколения чистит кэш runner'ов.

Тестового раннера во фронтенде нет (`web/package.json` — только `dev` и
`build`), поэтому клиентская часть проверяется `tsc` при сборке и сквозным
прогоном через проектный скилл `verify`: собрать фронт, поднять оркестратор,
завести агента через UI, убедиться, что он появился в селекторе и отвечает, —
со скриншотом.
